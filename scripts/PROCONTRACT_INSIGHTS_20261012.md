# 开发思路与关键 insight

这是研究交接，不是把失败包装成成功。旧结论按当时源码和实验边界保留。

## 1. 责任、执行、学习是三层

```text
K：责任与证据边界       不能由执行者或研究者改写
Runtime：履责的推进      执行、冻结交付、独立检查、修复、停止、恢复
P / M / H：实验策略      执行提示、研究方法、有限 checkpoint 条件
```

K 应尽量小：执行者提出，证据支持，授权者结清。模型说完成、流程休息、
自动验收支持、责任解除，不是同一个事件。Within-reach 证据衡量 diligence，
不是自动获得独立确认。高功能分数不能替代权限与证据的正确性。

同样，所有任务一律失败也不能证明 kernel 有用。必须同时有已知正例、反例、
未知状态、故障恢复测试，以及保留真实成本的任务对照。

## 2. 最重要的实际缺陷：账本存在不等于继续履责

旧 native 正常关闭并 thread/resume 后，合同仍在 SQLite，状态却重置为 idle、
contract_id=null。修复没有重新签约，而是重建同一责任：

- 校验合同事件链与当前合同一致，核对已签发条款和证据/捕获策略。
- 从原始内容寻址快照恢复 base，不把当前工作区误当原始输入。
- 保留 repair 次数；已接受 defeat 后的未知窗口不能返还修复额度。
- resume 本身不重放 worker、检查或修复。新一轮输入重新交付和验收。
- 恢复证据不一致时停止自动化，但保留已知责任身份。

117 个扩展测试通过。原生回归在旧包失败，在修复包通过，并覆盖恢复后的
第二次交付。模型为本地 scripted fixture，证明控制机制，不证明真实模型能力。
实现：`controller/runtime/recovery.rs`；原生回归：`test_procontract_resume_native.py`。

## 3. 这轮 RSI 学到了过度收敛，而不是可靠地提高探索效率

P0 只建议“做有辨别力的检查，验证可交付物”。V1 加入“不再开第二个探索分支”、
“验证后停止”；V2 进一步把非零或不明确结果当停止信号。

观察与这类退化相符：sox 命令数 568 → 315，native 时间 86.4 → 47.8 分钟；
peco 命令数 208 → 101，时间 38.7 → 16.9 分钟，质量均下降。两者都未撞时限。
这是值得修正的诊断，不是 N=1 已证明的唯一因果解释。

**元研究只许试一个候选，不等于执行者只许做一个实验。** 安全限制应约束
权限与总资源，不能无意中禁止解决问题所需的探索。

## 4. 有限观察应保留进展结构，不只是活动计数

两次研究的 1200-byte 观察包实际都只保留了一条最近命令，以及若干计数。
这不足以判断重复探索、需求覆盖、剩余能力缺口或信息增益。

后续应使用有界的“义务 → 证据 → 未知 → 下一项可辨别实验”摘要，而不是
无限扩大上下文。预期错误和非零退出也可能是有价值的黑盒观察。

## 5. 代理指标、真实回报、因果信用不能混为一谈

这轮研究预测侧偏向 command_failure_fraction；第二次命中目标，但功能质量仍差。
选择器主回报仍是独立提交后质量与成本，不是命令成功率；问题是提案优化了
不充分的代理指标，而稀疏反馈没有及时纠正它。

回报归属于最初选定的整体控制器及后续轨迹，不能独立归功于子代 P、M 或 H。
异质任务、每组一次、不断扩展的版本池也不足以支持强统计或 regret 声明。

## 6. 文本改变、ACK、实际作用、收益是四个台阶

- M0 的输出中有 M1，不代表 M1 被使用；要绑定后续研究的实际输入。
- ACK 不代表策略进入已完成的模型请求；要有严格消费见证。
- H 从阈值 4 改到 8 时，已有 42～49 个命令完成，双方都为 true。
  JSON 变化不代表决策变化，更不是 harness 收益。
- 策略里写“下降就 revert”不是已经实现了回滚。

候选应先检查在实际可达且被 Host 允许的状态中是否改变决策，再做前瞻收益验证。
离线重放可以排除无效更新，但不能替代真实效果测量。

## 7. Coverage 与 merit 分开

预声明的前两次 coverage 探针用于执行 seed → child → grandchild，不是因为
child 已证明优越。探针真实 propensity=1；第三次才自然采样。

本轮第三次在固定版本池、同一随机数的事后重放中，反馈确实使选择由 research
变成 hold。但实际任务随后签约失败，没有完成评分闭环。不能据此改写验收 FAIL。

这是一种冻结底模、在程序/策略空间做的有界在线学习；不是权重训练。
M 的递归执行有证据，通用 RSI 收益没有证据。H 当前只是 checkpoint DSL，
不是任意修改 runtime 源码。

## 8. 实验生命周期本身也是系统的一部分

- Missing / invalid / interrupted 不能变成分数 0；失败实例不能从矩阵中消失。
- 不重跑择优，不重新命名已经曝光的任务，不修改终结研究的旧 verdict。
- 保存代码/镜像/评测/提交摘要、预算、真实调用、成本与清理结果。
- 外部榜单模型、预算、环境不同，只作参照。作者历史曝光已披露，不称 globally unseen。
- Human engineering repair 不是 RSI 自我改进；模拟模型 E2E 不是真实模型收益。

## 9. 下一个应解决的问题，按优先级

1. **凭据生命周期**：vanilla 首题因运行中 key 过期而中止。启动时读一次环境变量
   不足以支持小时级任务。先做 TTL/轮换与错误分类设计，不能靠同一过期 key 重试。
2. **契约输入可靠性**：drafter 的 `7` 不是 Host 发出的 `request:7`。
   应约束合法引用、定位错误字段，不以放松来源/意图校验来提高“成功率”。
3. **预算内的进展调度**：固定一次 repair 会导致责任仍 outstanding，却没人继续工作。
   在 pure kernel 外，依据残余义务、进展与预算决定继续/修复/终止，拒绝无限重试。
4. **稳定性与实验隔离**：保住 P0 和稳定策略；实验谱系允许试错，稳定部署需要收益证据。
5. **再研究 M/H 升级**：有可作用的 H、有足够信息的 M，以及各自的消融，才谈进一步 RSI。

当前推荐 ProContract-only 是审慎的运行选择，不是宣布 ProContract 已战胜 vanilla。
长期架构方向仍是：**责任不逃逸，探索不盲缩，更新有可检验的行为与收益。**
