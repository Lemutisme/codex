# Starting evidence-based insight intake into RSI

The user authorized absorbing successful/failed trajectories while improving RSI.
The first intake deliberately samples twelve completed cases, existing source-linked
analyses and concrete controls. It is not an assertion that all two hundred
trajectories have received deep analysis.

Inputs and real-model trial artifacts:
`/data/ProContract/procontract-insight-rsi-20261102/`.
`corpus/bundle.json` binds the original files and distinguishes observation records
from prior analysts' interpretations. Its imported source bytes stay available even
if an original path later changes. The fixed benchmark and its scores are unchanged.

## Stable lessons to test and reuse

| Direction | Success evidence | Failure/counterevidence | Scope of transfer |
| --- | --- | --- | --- |
| Use a representation capable of the needed behavior | Shellharden's source spans/lexical state; loop's execution state; real ping/HTTP/ZIP behavior | Narrow lookup/fallback implementations cannot cover arbitrary composition; a high score does not identify every necessary method | Strategy chooses representations and available resources according to the actual task; no domain algorithm enters the kernel |
| Make an observation reach the intended path | PTY input-preservation control, runnable local-server/fixture comparisons, boundary probes after a fixed suite passed | Missing grader routing, unavailable tools/fixtures and partial checks do not measure the intended behavior | Harness exposes actual conditions; strategy constructs a useful experiment and interprets what it establishes |
| Preserve useful work without certifying too much | Strong artifacts coexist with internal Support=false; targeted repairs improve related behaviors | Repeated reviews, fixed sample counts and protocol errors do not establish whole-task quality | Keep artifact quality, execution, measurement scope and acceptance distinct |
| Retain facts and corrections in usable form | Reusable probes and source/commit identities permit continuation | False rollback narratives and stale summary views caused wrong explanations or repeated work | Retrieve actual records, preserve contradiction/scope, and bind a decision to the subject and conditions it concerns |
| Improve a method only within the evidence | New boundary/interaction observations remain useful after fixed internal comparisons saturate | More calls, successors or reviews do not by themselves establish improvement | Context-level research selects hypotheses/experiments; no universal sample, retry or gain gate is added |
| Preserve original responsibility and resource scope | Stopped artifacts can be recovered without renewed inference; selected waiting need not end the task | Caller loss, missing finalization, changed context and local allocation expiry can be mistaken for task completion | Kernel semantics already separate responsibility and authorized transitions; harness must retain execution facts and deliver current input |

These are scoped mechanism hypotheses and implementation principles. They are not
isolated causal estimates of the Vals score differences. The corpus also includes
contrary evidence: a poor aggregate can coexist with a real protocol implementation,
an internal tally can improve while an input channel remains absent, and a benchmark
can define a numeric penalty even when execution completeness is false.

## Implemented path

The existing kernel is unchanged. The operation host now supplies source custody,
bounded source views, snapshot retrieval, explicit applicability/counterevidence,
and an input-delivery view with an exact acknowledgement boundary. Duplicate imports
and duplicate delivery keep the same objects/assignments. Reusing a responsibility
ID with changed terms cannot silently reinterpret its original bindings.

Native execution is a shared adapter, with explicitly offered capabilities and
observed model/context identities. The caller can select an action on pending input;
the harness does not decide that each failure must cause an analysis, patch or
promotion. Research workflow remains supplied context. Local finite experiment
allocations do not make a hard deadline mandatory for the standing responsibility.

The pilot uses real GPT-5.6-Luna/max ProContract invocations with no model-request
ceiling. The standing research authority has no deadline. E1 used four protected
structural controls; E2 adds a finite studied-deadline counterexample. These exercise
current-subject evidence, unavailable measurement, explicit scoring convention and
action-versus-standing-task scope. Their data/expected outputs remain
outside the research actor view. This is a bounded research-context test, not a new
ProgramBench result or a claim of broad transfer.

The research actor receives the actual corpus and the existing strategy's control
outcome, retains its own knowledge, and chooses whether to propose/test/select a
research-context revision. Keeping the incumbent is legitimate. A later research
action uses the selected version and retrieves retained knowledge while examining
the actual completed Pandoc outcome. Model-authored artifacts and selected-version
use must be checked from the retained records before claiming operational closure.

## Validation boundary

Fifty-one Python controls pass. They cover the existing operation/adoption
invariants and the new source identities, bounded byte views, correction retrieval,
input acknowledgement interleavings, repeated issue identity, offered capabilities,
native output custody, long workspace paths, cross-host knowledge/source retention,
source paging verification and concurrent container disappearance. An actual offline Docker control
also connects through the read-only socket mount with zero model calls.

Read-only visibility is still reach. The native actor sees runtime binaries and
explicit inputs, not host scripts/measurement manifests; output collection also
refuses to read through an actor-created symlink into the host. These bounds matter
to the meaning of protected experiment evidence.

## First real episode and the next iteration

E1 completed with GPT-5.6-Luna/max. The established strategy passed 3/4 protected
controls (37 requests). The research actor created three scoped knowledge entries,
proposed a work-method revision and tested it: 2/3 observed controls passed, with
one additional control unavailable (43 requests in that candidate experiment).
It retained the incumbent. The subsequent Pandoc analysis read and cited the three
knowledge entries and retained a fourth. The final research cursor was 58 with no
pending input and an event wait selected. These request subtotals exclude the
research and follow-up actions; final accounting must include those too.

The unavailable control exposed a harness observation defect: bulk Docker inspect
returned partial output when a foreign container disappeared. The adapter now
rechecks missing live IDs and rescans its owned mount scope. A later independent
inspection confirmed E1's shutdown; this does not rewrite its historical result.
Source verification is also cached by filesystem identity/change metadata so
bounded pages do not repeatedly hash an entire large retained artifact.

Two analytical problems supply input to E2. A control confused a native invocation
allocation with the studied responsibility's absent deadline. The adapter now
exposes both scopes as factual context, and the control contract explicitly asks
for the studied limit, including a finite counterexample. The Pandoc follow-up
also called a local `repairs_used=0` counter "zero repairs" despite 15 successor
returns and 30 captured subjects in its retained ledger. Those counts do not
establish 15 successful repairs; they refute the counter's use as total execution.

E2 imports the four E1 knowledge roots and their 35-record cited closure, preserving
identities, conditions and retained bytes without transferring execution/adoption
authority. It receives the counter-scope evidence and E1's result as further inputs.
A follow-up is explicitly a new analysis request over the same Pandoc artifact,
bound to the preceding research outcome and selected version; it is not a new
benchmark result. E2 uses the same private controls for its baseline and candidate.
Because its harness and control contract changed, E1 and E2 pass counts cannot
establish a causal gain between episodes.

Neither successful controls nor retained insights alone imply broad performance
improvement. This work implements task-time context/tool learning, not model-weight
reinforcement learning. Final E2 results and full request accounting remain to audit.
