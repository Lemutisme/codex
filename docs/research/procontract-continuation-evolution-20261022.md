# Assessment meaning and context-selected continuation

The preceding ProgramBench cohort produced valid external results: LuaJIT 81.97%,
ripgrep 82.83%, treemd 57.74%. Ripgrep and treemd stopped with 268 and 464 requests
remaining. Their reviewers treated finite coverage or missing historical evidence
as request/terms discrepancies, and the adapter excluded the corresponding
behavior findings from repair. These scores and trajectories remain unchanged.

This revision separates three responsibilities in the existing adapter:

1. **Meaning:** new review schemas describe an omitted, added or altered request
   obligation, its exact request quote where applicable, and affected catalog IDs.
   An added obligation with no source may refer to the complete request using a
   null quote. The host checks supplied anchors and IDs. The strategy distinguishes
   these discrepancies from missing evidence and incomplete coverage; the host
   does not invent a keyword-based semantic classifier. Legacy retained reviews
   remain readable with their original restrictions.
2. **Knowledge:** independently supported claims, observations, counterexamples,
   missing evidence and scope reports remain attached to their frozen subject.
   A continuation neither changes the assessment nor certifies acceptance.
3. **Work selection:** a replaceable `continuation.md` prompt receives the original
   request, scoped assessment, public evidence reference, actual offered execution
   capability and available resource context. It selects resume, successor or rest
   from those offered actions, with obligation IDs and a concrete next step.

The selection also receives the preceding choice as historical intention, the
actual configured public-check commands/invocations and the bound host-observation
limitations. Missing history is reported as unavailable, not as an empty history.
This exposes why a method may fail to produce the evidence the next reviewer can
observe; it does not impose a retry count or infer that an unobserved action never
happened.

The harness validates and records that selection before dispatch. Disputed IDs
and confirmed execution violations cannot be selected as repair targets. The
same original allowances, owner epoch, request gateway and executor-lifetime rules
remain in force. A local reservation survives a failed dispatch or restart; a
selection that rests spends no local execution attempt. New verification records
identify the continuation policy so recovery no longer treats every new Defeat as
an executed repair. Old records keep their previous conservative accounting.

An unresolved review can therefore produce
`Issue → Propose → Propose → Support` after additional observation, without inventing
a Defeat. Conversely, strategy can rest after a retained Defeat rather than being
forced to launch another executor. Infrastructure/lifetime uncertainty does not
gain a blanket retry path. Interrupted strategy inference is explicitly recorded
as execution interruption, retaining the original assessment and responsibility.

Verification summaries and successor transport no longer prescribe a particular
investigation/repair sequence. Those instructions are supplied as strategy context.
The pure kernel and store are unchanged. Preparation, final-review scheduling,
one review-protocol correction and the legacy allowance-mode interpretation remain
migration work. This patch is not complete orchestration decoupling or RSI.

## Real trajectories and final-build validation

The first all-model cohort ran the intermediate continuation build before the
preceding-choice/observation-scope fields were added. Both artifacts passed their
frozen external checks, but repeated attempts to obtain unavailable execution
receipts consumed the qualification allocation. That failure motivated the final
context transport change; the earlier attempts were not resumed or rescored.

| Build / task | Frozen external checks | Internal result | Requests / minutes |
|---|---:|---|---:|
| Intermediate / Unicode range edits | 321/321 | Qualification watchdog; Support=false | 188 / 30.01 |
| Intermediate / topological-order counting | 172/172 | Qualification watchdog; Support=false | 192 / 30.02 |
| Final / unified diff application | 261/261 | Support | 115 / 28.56 |

The final task used real GPT-5.6-Luna/max in every role. Its exact native sequence
was `Issue → Propose → Defeat → Propose → Defeat → Propose → Support`, with two
successors under the same responsibility and original open-ended allocation.
Independent review found two defects outside the frozen grader examples:
nonstandard JSON constants were accepted, and a valid decimal coordinate containing
5000 leading zeros followed by 1 hit Python's integer-string limit. Both were
repaired. A separate post-run replay on the final immutable artifact passes 5/5:
NaN, Infinity, -Infinity, the long-zero coordinate and following-line continuation.
Original 261/261 and source hashes remain unchanged.

The final run recorded one locally rejected support citation, corrected within the
same review, plus three tool errors: a malformed patch, an exhausted computation
allowance and a missing tool field. These did not erase independent counterexamples.
Do not describe this as zero malformed model invocations.

A separate final-build native control with real Luna/max continuation selection
preserves `Issue → Propose → Propose → Support` for an evidence gap. Other roles in
that control are scripted. A read-only strategy replay of the earlier counting
receipt gap chooses the available independent diagnosis capability and explicitly
separates fresh observations from missing historical receipts. No action was
executed in that replay, so it does not establish that the alternative closes the
historical acceptance gap or eliminates every repetition.

Four real reviewer interpretation controls produce the expected distinction
between evidence gaps and actual request/terms discrepancies. One also emits an
inappropriate artifact finding on the genuinely disputed obligation; its named
scope dispute keeps that finding outside actionable repair. These controls do not
establish universal semantic correctness.

Independent mathematical inspection confirms the counting recurrence and its DP
implementation. Its prefix terminology could be made more explicit, and a separate
CLI probe rejects a valid request containing a 5001-digit integer in an allowed
unused field. This is a concrete untested input boundary, not a reason to alter the
172/172 score or reject the correct mathematical argument. The range-edit deep JSON
counterexample was independently replayed and passes after repair.
