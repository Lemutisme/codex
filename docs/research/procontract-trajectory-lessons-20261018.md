## 已观察到的问题

1. **执行者失去继续查询参考的能力。** bat 尝试移动参考失败，随后 unlink 原路径；
   ast-grep 的构建也替换了原参考路径。后继看到的是候选。宿主的独立检查仍保有参考，
   但执行者只剩旧输出与文档。只执行的文件权限不能阻止可写父目录中的删除。
2. **判定反馈没有转成可执行的诊断。** bat 四次正式交付内部均为 116/208，逐项状态
   签名也相同；残差重复宽泛类别，公开失败为零。ast-grep 为 81→83→83→81，同分期间
   也存在相反的修复和回归，最后一个已通过的公开重写行为重新失败。
3. **核心表示不足。** ast-grep 依靠 token/括号/跨度启发式，CLI flags 为 20/23，
   selectors 为 0/20、两个 transforms 模块合计 0/51、scan rules 为 6/54。
   bat 普通输出为 37/43，但 syntax 为 4/34、vscreen 为 2/37、cache 为 5/21。
   这些结果指向应深入验证的核心语义和模式交互。
4. **审查被验收条件阻断。** 三题共九次正式交付均未运行 reviewer；机械失败或证据
   门槛先行返回，使诊断审查无法参与这些失败状态。
5. **额外次数门槛提前停止。** bat/ast-grep 都用完三个后继与八次进度发布后结束，
   分别仍有 424/343 次模型请求和约 283.5/281.5 分钟原始预算。

## 可推广的原则与下一轮验证

| 原则 | 具体机制 | 如何判断改进是否有效 |
|---|---|---|
| 保存已完成工作及继续验证的能力 | 固定输入与候选构建分开，参考/数据/方法跨交接可用 | 后继仍能进行新的独立对照，无需猜测或重建输入资产 |
| 用具体发现指导修复 | 内部诊断提供可复现条件与差异；官方隐藏评分保持独立 | 修复能关闭对应反例，并改善邻近行为 |
| 让已学到的行为成为持久资产 | 将反例、修复与可执行回归检查一同保存 | 新改动是否保持原来已验证的行为，回归能否及时发现 |
| 停滞时检查假设与实现表示 | 根据未改变的失败选择诊断、改方法或交接 | 后继产生新的可验证进展，而不只是新的提交与更长代码 |
| 未知影响它实际依赖的结论 | 按观察属性保留信息，隔离局部超时，允许诊断性审查 | 动态输出不抹掉稳定性质，局部问题不取消无关工作 |
| 统一预算服务于任务目标 | 在原始授权内安排工作、验证和后继 | 少受无关次数门槛阻断，并提高单位资源的实际产物质量 |

这里的“通用”体现为问题结构相同：数学要保留假设与已证引理，研究要保留数据和实验
方法，流程任务要保留阶段交付与继续执行的能力。工具、具体检查和完成条件由领域
提供。责任 kernel 继续管理职责、对象、证据引用与授权；不要将这些经验变成新的
普适数值门禁。

下一轮开发优先解决输入资产与构建输出的分离、可操作诊断与回归记忆，然后协调预算
和诊断审查。验证同时关注最终质量、关闭/重新出现的具体缺陷以及资源效率。
Support 的准确性是验证器指标，不能取代产物成绩。
