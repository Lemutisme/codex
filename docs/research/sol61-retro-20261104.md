## Confirmed publication defect and repair

The Eureka trace calls `publish_progress` with request `checkout-state-review-1`.
The actual return is `symlink .work/visual_only-0thhj9pl/bin/code points outside the
workspace`. Source: its archived root session,07:40:29 UTC, lines432–434.
The publication reservation remains pending. Later calls return `a prior publication
has unresolved effects`, and the controller ultimately rests despite time remaining.

The code resumes the capture barrier before propagating the snapshot error. Therefore
this observed local failure has a confirmed execution boundary; no assessment was
dispatched. Treating it as permanently unknown was incorrect. Six selected traces
contain analogous capture refusals: external symlinks, non-UTF8 fixture names or an
oversized generated file. Elfcat's earlier invalid `continue_from` is a separate
pre-reservation error; its later non-UTF8 capture error matters to the pending state.
The other three pending-publication stops still need reconstruction of their first
failing stage. They are not declared fixed by this evidence.

The harness now persists `progress_failed` with scope `publication_operation` after
confirmed resume, and for local materialization failure before assessment dispatch.
The failure retains its request/options and original spent reservation. Same-request
reuse returns the recorded error; a new request can proceed. A durable failure record
also repairs a crash between outcome persistence and grant finalization. Evidence
access exposes these failures separately from artifact judgments. Unknown external
effects remain blocked. Snapshot restrictions and kernel acceptance semantics remain
unchanged.

Validation:

- A real external-symlink snapshot regression fails on the baseline. The first test
  compilation lacked imports and the first crash simulation reserialized CAS bytes;
  those test setup errors and the corrected baseline failure remain in the logs.
- All250 extension tests pass, including15 publication tests. They cover caller loss,
  real snapshot refusal, retained-error retrieval, original-budget preservation,
  crash recovery without replay, and unresolved-effect rejection.
- A real Sol/max native app-server/Docker control deliberately causes the snapshot
  refusal, removes the offending link and successfully publishes again. The ledger
  contains two finished requests with no pending reservation. All26 model requests
  share its original480-second diagnostic allocation. An initial preparation timeout
  is retained; it did not reserve a publication or renew the allocation.

Evidence: `progress-baseline-v2.log`, `extension-tests.log`, and
`native-publication-control/result.json`. This proves the scoped execution repair,
not a ProgramBench score increase.

## Grading conditions and closure

The final Dog candidate and reference were executed in the same pinned offline image.
They match exit status, stdout and stderr on four probes, including two public-DNS
invocations whose official tests expect success/empty stderr. Both instead report
network unreachable. The version and localhost-refusal controls also match.

The pinned evaluator's `_new_env` adds `--network none` for non-testing/compilation;
the testing branch deliberately omits it (`src/programbench/eval/eval.py:448–480`).
Our campaign Docker wrapper adds `--network none` to every container. Thus an execution
restriction was applied beyond the solver/compile stage to the grader's test stage.
The solver's offline rule is valid; the global wrapper is the wrong owner for extending
that rule to a different stage. `dog-paired-network-control.json` and the retained
evaluator/wrapper sources establish this discrepancy. They do not establish how many
of Dog's822 failures it explains, or a corrected score. Historical candidate defects
and all raw scores remain intact.

Oha has a different closure problem: initial cleanup failed, but post-native-shutdown
cleanup confirmed no remaining containers. The retained historical error still caused
the driver to refuse submission freezing. Current verified quiescence should determine
whether capture is possible while the earlier error remains an execution observation.

`deployment-candidate.patch` contains minimal corrections for a future frozen deployment:
preserve the caller's stage-specific network arguments and use final native/environment
closure for submission capture. Three controls pass: replay Oha's retained closure
receipts through actual packaging; reject active/unknown writers; preserve explicit
solver isolation while leaving the official grader's selection intact. This candidate
has not been installed into the live frozen campaign or used to produce a replacement
benchmark aggregate. Environment qualification and artifact-only rescoring remain
separate work; no solver restart or renewed budget is needed for that measurement.

Felix's recursive fuzz trees exceeded Python evaluator extraction and retention path
handling limits. Keeping reproducible probe recipes separate from disposable generated
trees addresses the observed task strategy. Silently discarding arbitrary paths or
weakening capture boundaries is not the harness repair proposed here.

## Strategy and RSI absorption

The task strategy replaces, rather than merely appends to, its dependency/fixture
guidance: use a trusted control under comparable conditions to investigate a disputed
measurement; apply permissions/limits to the stated actor/operation; preserve probe
generators and observations while separating nonportable disposable trees from delivery.
The research method now explicitly retains a raw score alongside a scoped correction
of its causal interpretation. These are context choices, not code-selected workflows.

The existing native RSI runtime processed the new records with Sol/max, retained
source-linked knowledge and proposed W1/W2/M1 context edits. A fresh owner input supplied
the paired Dog control and the evaluator source; the preceding22 charged requests and
interrupted action remain accounted. The subsequent analysis recovers prior work,
corrects attribution and distinguishes inspected sources from owner-reported facts.
The developer reviewed and condensed the proposals into the task and research strategy
files. This is an inspected E2E research/development loop, not unattended self-promotion.

That analysis retained both reports and five knowledge records, then exhausted its
900-second action allocation after59 requests before selecting a final wait. The
runtime retained the outputs, confirmed shutdown and exposed `needs_selection`;
it did not certify completion or silently replay the action. Development validation
and the requested final disposition are handled as subsequent scoped work under the
same continuing research responsibility. The expired action and its costs remain.
