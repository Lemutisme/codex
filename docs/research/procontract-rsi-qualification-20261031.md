## Implementation

The kernel/store source is unchanged from delegated base
`454b2ba00fffad94e4262da9989eb682d5fdb853`. Ordinary work, continuing improvement and
scoped adoption use distinct responsibilities through that same implementation.

`scripts/procontract_operations.py` supplies definitions, resolved inputs,
observations, knowledge/corrections, explicit assignments, durable dispatch and
reconciliation, cancellation, pending input, selected waits and fenced adoption.
The socket authenticates the admitted responsibility and offered capabilities;
the actor cannot provide human provenance, replace its evaluator, expand editing
scope or select a research version as the task deployment.

Research orchestration is replaceable context in
`strategies/research/operations.md`. Knowledge does not select behavior. No
analyst/challenger sequence, task-count schedule, empirical numeric gate or new
workflow language is built into these operations. The old RSI driver remains a
historical interface and is not imported by the new host.

Native action finalization outlives caller cancellation. Publication ownership
outlives tool transport. Inspection assessment and teardown await known local
owners; unknown historical effects stay unknown. Confirmed check/reviewer failure
can return to strategy without becoming artifact failure or selected rest.

Adoption uses the existing atomic Discharge + incumbent-selection transaction.
Identical retries preserve their original receipt, including lost acknowledgements
and later expiry; changed requests and stale incumbents fail. A later accepted
kernel defeat makes the selected version unavailable while retaining the real
selection sequence. Choosing a fallback requires an explicit new decision.

source and its fixed cases. Read-only visibility is still reach. Their claimed
beyond-reach qualification was invalid, regardless of whether the observed actor
read that file. Those isolated settlements were explicitly defeated through the

measured outputs and model trajectories were retained. The current incumbent view
refuses those selections. **E4 is a mechanical rollout observation, not a legitimate
beyond-reach adoption result.** E5 uses restricted runtime mounts and fresh
