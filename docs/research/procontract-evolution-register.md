## Strategy: three responsibilities to improve

| ID | Essential direction | Supporting observations | Qualification target |
|---|---|---|---|
| S1 | Select work by its contribution to the user's outcome or a consequential decision | Useful local-server/fixture experiments; repeated review/hygiene loops; improving internal comparisons with limited external coverage | Appropriate implementation, information/capability acquisition, review, delivery and waiting choices, including open-ended tasks with user time expectations |
| S2 | Learn an applicable rule and test the boundaries relevant to the task | Narrow lookup repairs; high-score byte/default/configuration residuals; resource-conditioned behavior mistaken for a universal rule | Changed inputs, compositions and conditions when transfer is required, with controls where exact bytes or a finite catalog are the real goal |
| S3 | Accumulate and reuse knowledge through accurate current-state context | Eleven commit-discrepancy narratives conflict with delivery/tool/context facts; retained evidence and experimental assets can support successors | Accurate state claims, reuse of applicable evidence, targeted revalidation and continuation without restarting all reasoning |

S1 should consider resources actually available: existing systems/libraries, primary
sources, data, computation, tools, authorized collaboration and external events.
Clean-room/offline/six-hour restrictions belong to this benchmark profile. More
resources broaden options; they do not require using every option or exhausting them.

S2 allocates breadth and precision according to the task. A central capability gap
may matter more than a small residual; an exact-byte difference can also be the
central requirement. No universal final audit, sample count or review reserve
follows. A theorem's remaining proof gap is not resolved by successful examples.

S3 distinguishes authority from factual support. Prior model statements cannot
create permissions or certify success, but untrusted does not mean false. Use
retained facts with their versions/conditions. Test context organization and wording
separately: context size alone is not a proven cause. Unchanged bytes may deserve
a new observation; unchanged-source evidence does not certify changed external state.

## Kernel boundary and later work

These observations do not presently require expanding the kernel. Preserve
domain-independent progress/responsibility, evidence coordinates and authorized
transitions. No benchmark threshold, mandatory workflow, retry count, universal
countdown or numerical quality score follows. Useful partial work, outstanding
responsibility and completed acceptance stay distinct.

Qualify execution continuity (H1) and measurement fidelity (H2/H3) as independent
prerequisites, including grader dependencies/connectivity and large-result handling.
Prefer recovery from frozen artifacts while preserving original failures.
Then hold the qualified harness
fixed while comparing S1–S3 context/skill variants with the same model settings and
actual resources. Context replay can diagnose interpretation, but cannot establish
end-to-end quality gains. Fresh ProContract E2E validation should include connected
maintenance, theory/research, asynchronous work, changing conditions and tasks with
no hard deadline. No such new experiments are launched by this register.

Integrate each new finding into an existing direction when it changes the mechanism,
scope or needed validation. Add a direction only for a distinct missing capability
or method; do not append a permanent prompt paragraph for each residual.

The [E2E meta-analysis/RSI architecture](procontract-rsi-e2e-architecture-20261031.md)
specifies how that process can become ordinary authorized work under the same
kernel. It separates scoped knowledge, candidate versions, experiments and actual
adoption, and requires the selected version to be used by a subsequent task before
claiming automatic rollout. The user has now delegated implementation to one
Astra xhigh agent in an isolated branch; no automatic loop is enabled in the fixed
campaign. The parent continues [test-time feedback analysis](procontract-test-time-feedback-20261031.md)
with quality, execution, measurement conditions and cost kept separate.

The [positive-trajectory comparison](procontract-positive-trajectories-20261028.md)
adds five cases above the frozen Vals Luna/max reference. It supports the existing
directions through real socket/HTTP behavior, reusable parser regressions, explicit
loop state and a corroborated PTY input-preservation repair. These local mechanisms
are distinct from attributing the entire score gap to ProContract or extra compute.
